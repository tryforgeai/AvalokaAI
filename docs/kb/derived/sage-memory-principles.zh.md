# Avaloka 的 SAGE 记忆原则

处理状态：已为 R1 SAGE Lite 记忆实验进入运行时研究链路。

这份派生笔记把 SAGE 论文翻译成 Avaloka 的本地记忆规则。

## 原则 1：记忆不是聊天记录

Avaloka 不得把长期记忆当成保存原始情绪对话的地方。

好的记忆：

- “用户更喜欢短的、身体落地的回应。”
- “病痛恐惧出现时，避免惩罚/还债框架。”

坏的记忆：

- 完整粘贴的对话
- 具体私密细节
- 类似诊断的结论

## 原则 2：Writer 和 Reader 必须分离

Memory Writer 判断什么可能值得保存。

Memory Reader 判断当前什么相关。

不要把它们混成一个模糊的 LLM prompt。分离模块让系统更容易测试、调试和改进。

## 原则 3：每条记忆都需要证据

没有来源证据的候选记忆必须拒绝。

允许的证据：

- turn IDs
- feedback IDs
- 明确用户反馈
- 重复确认过的模式

不允许的证据：

- 模型直觉
- 人格推测
- 推断出来的灵性意义

## 原则 4：稀疏记忆优于大型记忆

如果一条记忆不能改善未来照顾、安全或检索，就不要保存。

Avaloka 应该宁愿保存 3 条有用照顾事实，也不要保存 300 行历史。

## 原则 5：保存之前必须先过 Guardian

如果记忆保存了错误的东西，它会很危险。

Memory Guardian 必须拒绝：

- 医疗判断
- 危机手段
- 报复计划
- karma-blame
- 身份细节
- 原始对话
- 没有证据的人格标签

## 原则 6：检索必须很小

运行时 prompt 注入只能使用 3-5 条照顾事实。

绝不注入：

- 原始对话
- 来源 ID
- 私有日志
- 隐藏评分
- 推测性判断
- 完整记忆图谱

## 原则 7：反馈成为学习信号

用户反馈应该改善：

- 什么会被保存
- 什么会被拒绝
- 哪些事实会被检索
- 哪些 response moves 会被选择

反馈不应该变成侵入式画像。
