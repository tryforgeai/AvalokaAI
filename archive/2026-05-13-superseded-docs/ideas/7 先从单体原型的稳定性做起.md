从单体原型（Monolith）入手是非常明智的决策。在初期，减少网络延迟和分布式系统的复杂性，能让你集中精力调优**佛法逻辑**和**共情深度**。

在 Mac Mini 上构建这样一个稳定的单体原型，建议采用 **Python + FastAPI + LangChain + ChromaDB** 的技术栈。虽然你精通 Java，但在 AI 原型阶段，Python 的生态库能让你以最快速度完成从“论文算法”到“落地代码”的转化。

以下是为您设计的单体原型开发指南：

---

### 1. 单体架构设计 (The "All-in-One" Hub)

在单体模式下，所有的组件（LLM 推理、向量数据库、业务逻辑）都运行在同一台 Mac Mini 上。

- **接入层：** 使用 Streamlit。它能让你用纯 Python 写出美观的 Web 界面，非常适合原型展示。
    
- **逻辑层：** FastAPI。负责处理用户请求、调用 LangChain 编排 RAG 流程。
    
- **引擎层：** Ollama。通过本地回环地址 (`localhost:11434`) 与逻辑层通信。
    
- **存储层：** ChromaDB。它是嵌入式的（Embedded），数据直接存在 Mac Mini 的文件夹里，不需要额外部署数据库服务器。
    

---

### 2. 第一阶段：核心代码实现 (Week 1)

你可以先写一个最简单的 `app.py` 来打通链路：

Python

```
import os
from langchain_community.llms import Ollama
from langchain_community.vectorstores import Chroma
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain.chains import RetrievalQA

# 1. 加载本地 Embedding 模型 (在 Mac 内存中运行)
embeddings = HuggingFaceEmbeddings(model_name="BAAI/bge-small-zh-v1.5")

# 2. 连接本地向量库 (指向存放佛经的文件夹)
db = Chroma(persist_directory="./buddha_db", embedding_function=embeddings)

# 3. 初始化定制的 Avaloka AI (基于 Ollama)
llm = Ollama(model="avaloka-ai") 

# 4. 构建单体问答链
qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=db.as_retriever(search_kwargs={"k": 3})
)

# 5. 模拟用户提问
response = qa_chain.run("我最近工作压力很大，感到很迷茫。")
print(response)
```

### 3. 本周重点：数据的“因地制宜”

单体原型的稳定性很大程度上取决于数据的**清洗质量**。

- **数据入库任务：**
    
    - 找到《普门品》的现代白话译文。
        
    - 手动录入 10 段你认为最具“慈悲引导感”的大德开示。
        
    - 使用 `CharacterTextSplitter` 进行切片，建议每个分块（Chunk）大小在 300-500 字，并保留一定的重叠（Overlap），防止语境断裂。
        

---

### 4. 稳定性调优建议 (针对 Mac Mini)

1. **内存管理：** 如果你只有 16GB 内存，运行 Qwen-7B 约占用 5GB，加上操作系统和 Python 环境，剩余空间不多。**避免在开发时开启过多的 Chrome 标签页或大型 IDE**，确保 Metal GPU 拥有足够的统一内存。
    
2. **持久化：** 虽然是单体，也要做好数据的定期备份。建议将 `./buddha_db` 文件夹通过 Git 或云端进行同步。
    
3. **Prompt 缓存：** Ollama 默认会缓存最近的 Prompt。如果你发现第一次回答慢，第二次变快，这是正常的。
